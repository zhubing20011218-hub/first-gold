# 02 开发约定

## 一、钱

1. 钱只用整数。
   - 马来西亚的钱：单位是仙（sen）。RM 12.77 写成 `1277`。
   - 人民币：单位是分（fen）。¥21.07 写成 `2107`。
2. 变量名必须带单位：存仙的变量以 `Sen` 结尾，存分的变量以 `Fen` 结尾。例如 `priceSen`、`cashFen`。
3. **平台那一边的钱全部用仙来算**（售价、佣金、手续费、税、运费、平台打款）。**玩家手里的现金和成本用分来算**。
4. 仙和分之间只能通过 `src/engine/money.ts` 里的函数换算，不在别的地方自己乘汇率。
5. 汇率是固定值，放在参数表里，一局之内不变。
6. 一仙和一分不能再分。每一项费用算出来后，立刻四舍五入成整数，再参加后面的计算。

`src/engine/money.ts` 要提供的函数：

| 函数 | 作用 | 算法 |
|---|---|---|
| `applyBp(amount, bp)` | 按比例算一项费用 | `Math.floor((amount * bp + 5000) / 10000)`。`amount` 是不小于 0 的整数 |
| `senToFen(sen, cnyPerRmE4)` | 仙换成分 | 对绝对值算 `Math.floor((n * cnyPerRmE4 + 5000) / 10000)`，再加回正负号 |
| `fenToSen(fen, cnyPerRmE4)` | 分换成仙，只用于显示 | 对绝对值算 `Math.round(n * 10000 / cnyPerRmE4)`，再加回正负号 |
| `rmToSen(rm)` | 把 6.9 这样的数变成 690 | `Math.round(rm * 100)` |
| `yuanToFen(yuan)` | 把 12.34 变成 1234 | `Math.round(yuan * 100)` |
| `formatRM(sen)` | 显示成 `RM 12.77`、`RM 3,030.30`、`-RM 12.65` | |
| `formatYuan(fen)` | 显示成 `¥1,234.56`、`-¥20.87` | |

## 二、比例

1. 比例用"万分之几"的整数表示，变量名以 `Bp` 结尾。14.58% 写成 `1458`，3.78% 写成 `378`。
2. 汇率用"乘以一万"的整数表示，变量名以 `E4` 结尾。1 林吉特 = 1.65 元写成 `16500`。
3. 按比例算钱只用 `applyBp`，不直接写 `price * 0.1458`。

## 三、数量和时间

1. 件数、重量（克）、天数都是整数。
2. 时间只用"第几天"来表示，从 0 开始。一周是 7 天。不使用真实的日期和时间。

## 四、随机

1. 随机数只来自 `src/engine/rng.ts` 里带种子的生成器。
2. 需要随机的函数，把生成器作为参数传进去。
3. 取随机数的顺序要固定。不能因为界面上的操作顺序不同，导致同一局的结果不同。

## 五、参数表

每个参数的格式：

```ts
{
  value: 1458,
  unit: "bp",
  source: "B",
  note: "跨境直发的平台佣金率，默认 14.58%",
  public: true
}
```

来源等级：

| 等级 | 含义 |
|---|---|
| A | 平台公开规则，有官方出处 |
| B | 来自真实经营：项目负责人提供的数字，或他指定的费率计算器 |
| C | 假设或设计值 |

- `public` 为 `true` 的参数，以后会显示在游戏里"这些数字从哪来"的页面上。
- 缺少某个参数时，不要自己填一个数。停下来问。

## 六、文案和名称

1. 界面上的所有中文放在 `src/text/zh.ts`，组件通过它取文字。
2. 界面语言只有简体中文。
3. 游戏里的电商平台统一叫"平台"，不出现真实平台的名字和商标。
4. 不出现任何真实店铺的名字。
5. 代码注释用简体中文。变量名、函数名、文件名用英文。

## 七、TypeScript

1. 开启 `strict`。不使用 `any`，不使用 `@ts-ignore`。
2. 使用具名导出，不使用默认导出（React 的入口文件除外）。
3. `src/engine` 里的函数是纯函数：同样的输入得到同样的输出，不修改传进来的对象，不读写外部变量。
4. 一个文件只做一件事。文件超过 300 行就考虑拆开。

## 八、测试

1. 测试放在 `tests/`，文件名以 `.test.ts` 结尾。
2. `src/engine` 里每个对外的函数都要有测试。
3. `docs/` 里的"核对用例"必须一条不少地写成测试，数字照抄，不要改。一条用例一个测试，测试的名字以 `[G03-10.1#01]` 这样的编号开头，编号的规则见 `docs/13` 第 2.3 节。期望的数字直接写出来，不用被测的函数算。
4. 如果算出来的结果和核对用例不一样：先检查代码。确认代码是按文档写的之后，把差别报告出来，不要改用例。
5. 有一个"规则检查"测试：读取 `src/engine` 下所有文件的文字，确认里面没有 `Math.random`、`Date.now`、`new Date`，也没有引用 `ui`、`scene`、`plan`、`text`、`react`。

## 九、界面

1. 画面尺寸的要求见 `docs/01` 第八节。
2. 颜色、圆角、间距这些设计变量集中定义，不在各个组件里各写各的。
3. 动画要照顾"减少动态效果"的系统设置：用户开启后，动画改为直接显示结果。
4. 游戏运行时不发网络请求。断网也能完整玩一局。

## 十、依赖和安全

1. 新增依赖之前，先说明：为什么需要、体积多大、有没有不装也能做的办法。得到同意再装。
2. 任何密钥都不写进代码，不提交到 git。
3. `.gitignore` 必须排除 `node_modules`、`dist`、`.env`、所有 `.env.*` 文件和 `检查记录/自动/`。

## 十一、记录

1. 每个任务做完，在 `开发日志.md` 追加一段：日期、任务编号、做了什么、遇到了什么问题、项目负责人改了什么。
2. 每个任务做完，用 git 提交一次。格式：`<类型>: <中文摘要>`。类型用 `feat`、`fix`、`docs`、`test`、`chore`。
3. `过程截图/` 里的文件不要删除。
