# 04 经营模型（第 2 版：两年，八个季度）

这份文档规定：一局游戏里，每一天发生什么，钱和货怎么变化。

每单扣多少钱不在这里，见 `docs/03-每单结算规则.md`。商品的数值见 `docs/05-商品库.md`。

## 一、一局的结构

| 阶段 | 内容 |
|---|---|
| 开局 | 玩家选商品、选发货方式、决定第一批进多少货 |
| 经营 | 8 个季度，每个季度 90 天，共 720 天。每个季度开始时玩家做一次决定，然后模型一天一天往下算 |
| 收尾 | 第 720 天之后不再接新订单。模型继续往下算，直到货款全部到账 |
| 结局 | 算净资产，给出四种结果之一 |

- 天数从 0 开始。一个月 30 天，一个季度 90 天，一年 360 天。
- 第 `d` 天：季度 `q = Math.floor(d / 90)`，季节 `season = q % 4`，年 `year = Math.floor(q / 4)`。

店铺有两条赚钱的线，**共用同一批库存**：

| | 平台零售 | 批发大单 |
|---|---|---|
| 订单怎么来 | 平台推流和广告（第五、六节） | 每个季度的询价单，玩家报价去抢（第七节） |
| 费用 | 按 `docs/03` | 没有平台费用 |

## 二、玩家的选择

### 2.1 开局（`GameConfig`）

```ts
interface GameConfig {
  seed: number;
  productId: string;
  fulfillment: "cross" | "local";   // 开局时的发货方式
  startCashFen: number;
  firstStockQty: number;            // 第一批进货的件数
}
```

选发货方式时，必须把下面的区别告诉玩家（文字放进 `src/text`）：

| | 跨境直发 | 本土店 |
|---|---|---|
| 买家多久收到货 | 通常 7 到 12 天 | 大约 3 天 |
| 货款多久到账 | 签收后 15 天 | 签收后 7 天 |
| 每单的平台费用 | 较高 | 较低 |
| 补货 | 从国内进货，几天就到 | 要先运到马来西亚，时间长，还要付运费 |
| 开通费 | 没有 | 一次付清 |
| 风险 | 没有额外风险 | 有平台风控的风险，严重时会被封店 |

关于风控的文字只写"平台风控"，不解释原因，不显示数字。

### 2.2 每个季度的决定（`QuarterDecision`）

```ts
interface QuarterDecision {
  monthlyRestockQty: number;   // 每月初自动补货的件数。0 表示不补
  priceSen: number;            // 零售售价
  adBidFen: number;            // 广告出价：愿意为一次点击付多少钱。0 表示不投
  adDailyBudgetFen: number;    // 广告每日预算。0 表示不投
  bulkQuotes: { inquiryId: string; unitPriceSen: number }[];   // 对哪些询价单报价、报多少
  bulkShortChoices?: { inquiryId: string; choice: "rush" | "ignore" }[];   // 季度中间的选择，见第十六节。重放时用
  buyCompliance: boolean;      // 花钱做合规。只对本土店有效
  upgradeToLocal: boolean;     // 升级成本土店。只对跨境店有效
}
```

限制：

- `priceSen` 在商品的最低价和最高价之间，并且等于最低价加上 `priceStepSen` 的整数倍。
- `monthlyRestockQty` 是 0，或者不小于商品的起订量。
- `adBidFen`、`adDailyBudgetFen` 是不小于 0 的整数，由玩家自己填。
- `bulkQuotes` 只能对这个季度的询价单报价，每张最多报一次，`unitPriceSen` 是正整数。

## 四、随机数和市场热度

每一天、每一种用途各用一个独立的生成器，这样运气不受玩家决定的影响：

```ts
function dayRng(seed: number, day: number, stream: number) {
  const mixed =
    (Math.imul(seed ^ Math.imul(day + 1, 0x9e3779b1), 0x85ebca6b) ^
      Math.imul(stream + 1, 0xc2b2ae35)) >>> 0;
  return createRng(mixed);
}
```

| `stream` | 用途 | `day` 传什么 |
|---|---|---|
| 1 | 当天的市场热度波动 | 当天 |
| 2 | 自然订单的取整 | 当天 |
| 3 | 广告订单的取整 | 当天 |
| 4 | 跨境直发的送达天数 | 当天 |
| 5 | 退货 | 下单那天 |
| 6 | 开局时安排事件和询价单 | 0 |
| 7 | 每个季度风险值自动升高多少 | 季度编号 `q` |

"取整"指把千分之一单变成整数单：

```
orders = Math.floor(milli / 1000) + (rng.int(0, 999) < milli % 1000 ? 1 : 0)
```

市场热度：

```
yearBp        = year === 0 ? 10000 : year2DemandBp
noiseBp       = dayRng(seed, day, 1).int(demandNoiseMinBp, demandNoiseMaxBp)
demandBp      = applyBp(applyBp(product.seasonBp[season], yearBp), noiseBp)

competitionBp = applyBp(seasonCompetitionBp[season], year === 0 ? 10000 : year2CompetitionBp)
refBidFen     = applyBp(product.baseCpcFen, competitionBp)     // 对手的广告出价，显示给玩家
```

## 五、推流分

平台给店铺打的分，满分 100，五项各 20 分。**每个月初按上个月的统计重新算一次**，这个月内不变（价格那一项除外，它跟着当前售价变）。

```ts
interface MonthStats {
  wanted: number;      // 这个月来了多少零售订单（含没货发不出的）
  shipped: number;     // 发出多少
  lost: number;        // 没货发不出多少
  delivered: number;   // 签收多少（含退货的）
  returned: number;    // 退货多少
  delayed: boolean;    // 这个月有没有遇到运输延误
  bulkUnits: number;   // 这个月大单发出多少件（只用来算仓储费）
}

interface PushScore { sales: number; stock: number; price: number; complete: number; speed: number; }
```

| 项目 | 算法 | 上个月没有数据时 |
|---|---|---|
| 出单能力 `sales` | `benchmark = Math.floor(product.organicPerDayMilli * 30 / 1000)`；`ratioBp = Math.floor(shipped * 10000 / benchmark)`；分数是 `clamp(Math.floor(ratioBp / 1000), 0, 20)` | 第一个月用 `newShopSalesPts` |
| 近期发货水平 `stock` | `lostBp = Math.floor(lost * 10000 / wanted)`；分数是 `clamp(20 - Math.floor((lostBp - 200) / 100), 0, 20)` | `wanted` 是 0 时给 20 |
| 价格 `price` | `clamp(12 - Math.round((priceSen - refPriceSen) * 40 / refPriceSen), 0, 20)` | 不需要统计 |
| 订单完成率 `complete` | `retBp = Math.floor(returned * 10000 / delivered)`；分数是 `clamp(20 - Math.floor(retBp / 100), 0, 20)` | `delivered` 是 0 时用 `clamp(20 - Math.floor(product.returnBp / 100), 0, 20)` |
| 发货时效 `speed` | 本土店 `speedLocalPts`，跨境直发 `speedCrossPts`；上个月遇到过运输延误再减 `speedDelayPenaltyPts`，最低 0 | 不需要统计 |

```
total  = sales + stock + price + complete + speed
pushBp = pushBaseBp + total * pushPerPointBp
```

`pushBp` 的两个作用见第六节。

## 六、平台零售的订单

### 6.1 两个成交系数

```
priceFactorBp  = clamp(10000 - Math.round(elasticityE2 * (priceSen - refPriceSen) * 100 / refPriceSen),
                       priceFactorMinBp, priceFactorMaxBp)

ratingFactorBp = Math.max(ratingFactorMinBp, 10000 - (initialRatingE1 - ratingE1) * ratingStepBp)
```

### 6.2 自然订单

```
m = product.organicPerDayMilli
m = applyBp(m, demandBp)
m = applyBp(m, pushBp)
m = applyBp(m, priceFactorBp)
m = applyBp(m, ratingFactorBp)
organicOrders = 取整(m, dayRng(seed, day, 2))
```

### 6.3 广告

玩家填出价和每日预算。**实际能花掉多少由市场和推流分决定，不一定等于预算。**

```
ratioBp = Math.floor(adBidFen * pushBp / refBidFen)        // 推流分高，相当于出价被放大

shareBp =
  ratioBp <  adShareStartBp                    -> 0
  adShareStartBp <= ratioBp < adShareMidBp     -> Math.floor((ratioBp - adShareStartBp) * adShareAtMidBp / (adShareMidBp - adShareStartBp))
  adShareMidBp <= ratioBp < adShareFullBp      -> adShareAtMidBp + Math.floor((ratioBp - adShareMidBp) * (10000 - adShareAtMidBp) / (adShareFullBp - adShareMidBp))
  ratioBp >= adShareFullBp                     -> 10000

poolClicks      = applyBp(product.adClickPoolPerDay, demandBp)
availableClicks = applyBp(poolClicks, shareBp)

budgetFen        = Math.min(adDailyBudgetFen, Math.max(0, cashFen))
affordableClicks = adBidFen > 0 ? Math.floor(budgetFen / adBidFen) : 0

clicks     = Math.min(availableClicks, affordableClicks)
adSpendFen = clicks * adBidFen                              // 每次点击按自己的出价付钱

m = Math.floor(clicks * product.adCvrBp / 10)
m = applyBp(m, priceFactorBp)
m = applyBp(m, ratingFactorBp)
adOrders = 取整(m, dayRng(seed, day, 3))
```

## 七、批发大单

### 7.1 询价单

开局时用 `dayRng(seed, 0, 6)` 生成询价单，和玩家的决定无关（顺序见第九节）。从第 `bulkStartQuarter` 个季度开始才有询价单，之前的季度不生成，也不取随机数。之后的每个季度：

```
count = rng.int(bulkPerQuarterMin, bulkPerQuarterMax)
对每一张：
  qtyBp        = rng.int(bulkQtyMinBp, bulkQtyMaxBp)
  qty          = Math.max(10, Math.floor(applyBp(product.bulkQtyBase, qtyBp) / 10) * 10)
  dueDay       = q * 90 + rng.int(bulkDueMinOffset, bulkDueMaxOffset)
  rivalBp      = rng.int(bulkRivalMinBp, bulkRivalMaxBp)
  rivalBestSen = applyBp(applyBp(product.bulkRefPriceSen, rivalBp), year === 0 ? 10000 : year2BulkPriceBp)
  id           = "q" + q + "-" + 序号（从 1 开始）
```

玩家报价之前能看到：件数、交货日、`product.bulkRefPriceSen`（市场批发参考价）。看不到 `rivalBestSen`。

### 7.2 报价和中标

在季度第一天处理。对玩家报了价的每一张询价单：

```
effectiveSen = applyBp(unitPriceSen, 10000 - bulkRep * bulkRepStepBp)   // 信誉越高，报价显得越低
中标的条件：effectiveSen <= rivalBestSen
```

中标后：

```
valueFen   = senToFen(qty * unitPriceSen, cnyPerRmE4)
depositFen = applyBp(valueFen, bulkDepositBp)
shipDay    = 跨境直发：dueDay - headHaulDays；本土店：dueDay
warnDay    = Math.max(中标那天 + 1, shipDay - bulkWarnDays)
cashFen   += depositFen
```

没中标：发出事件，带上 `rivalBestSen`，没有其他后果。

### 7.3 留货、发货、交货、收尾款

```
reservedQty = 所有 status 是 "won" 的大单的 qty 之和
```

**零售每天最多只能卖 `Math.max(0, stockQty - reservedQty)` 件。**

| 时间 | 发生什么 |
|---|---|
| `shipDay` 那天 | `stockQty >= qty`：`stockQty -= qty`，`status` 变成 `"shipped"`。发货时是跨境直发的，付运费 `Math.ceil(qty * weightG * headHaulFenPerKg / 1000)`。`stockQty < qty`：违约，见下面 |
| `dueDay` 那天 | `"shipped"` 的大单变成 `"delivered"`，`balanceDay = dueDay + bulkBalanceDays`，`bulkRep` 加 `bulkRepGain`（最高 `bulkRepMax`） |
| `balanceDay` 那天 | `cashFen += valueFen - depositFen`，`status` 变成 `"paid"` |

违约：`status` 变成 `"defaulted"`；`cashFen -= depositFen`（退定金）；`cashFen -= applyBp(valueFen, bulkPenaltyBp)`（违约金）；`bulkRep` 减 `bulkRepLoss`（最低 0）；这个季度的违约次数加 1。不做部分交货。

## 八、本土店的风险

`riskPts` 只在本土店有意义。成为本土店的那一刻（开局就是本土店，或者升级的时候）设为 `riskStartPts`。

显示给玩家的等级：`riskPts < riskMidPts` 是"低"，`riskPts < riskHighPts` 是"中"，其余是"高"。

```ts
interface QuarterStats { wanted: number; lost: number; badReviews: number; bulkDefaults: number; }
```

**做合规**：季度第一天，本土店并且 `buyCompliance` 是 `true`，并且现金够：`cashFen -= complianceCostFen`，`riskPts = Math.max(0, riskPts - compliancePts)`。

**季度最后一天**（`day % 90 === 89`），只对本土店，按顺序做：

1. `riskPts += dayRng(seed, q, 7).int(riskQuarterMinPts, riskQuarterMaxPts)`
2. 这个季度 `lost * 10000 > wanted * riskStockoutBp`：`riskPts += riskStockoutPts`
3. `riskPts += badReviews * riskBadReviewPts`
4. `riskPts += bulkDefaults * riskBulkDefaultPts`
5. `riskPts = Math.min(100, riskPts)`
6. 如果 `riskPts >= riskHighPts`：
   - `auditCount === 0`：**审核**。`payoutFrozenUntilDay = day + 1 + auditFreezeDays`，`riskPts -= auditReliefPts`，`auditCount = 1`。
   - `auditCount >= 1`：**封店**。所有 `paid` 是 `false` 的订单批次，按 `applyBp((qty - (returnedQty ?? 0)) * payoutFenEach, banPayoutBp)` 一次到账，并标成已到账。`phase` 变成 `"banned"`，这一局结束。大单不再处理。

## 九、开局时定好的事（`Schedule`）

用同一个 `dayRng(seed, 0, 6)`，按下面的顺序取随机数：

1. **运输延误**，每年 1 次：对 `year` 0 和 1，日期是 `year * 360 + rng.int(delayMinOffset, delayMaxOffset)`。
2. **差评**，每年 `product.badReviewCount` 次：日期是 `year * 360 + rng.int(badReviewMinOffset, badReviewMaxOffset)`。和已有的差评日期相同就加 1 天。
3. **询价单**：按季度 `bulkStartQuarter` 到 7 的顺序，见 7.1。

效果：

| 事件 | 效果 |
|---|---|
| 运输延误 | 跨境直发：所有还没签收的订单批次，`deliverDay` 加 `delayDays`。本土店：所有还没到货的补货，`arriveDay` 加 `delayDays`。这个月的 `delayed` 记为 `true` |
| 差评 | `ratingE1` 减 `badReviewDropE1`，最低 `ratingMinE1`。这个季度的 `badReviews` 加 1 |

## 十、计算顺序

### 10.1 季度第一天，先处理这个季度的决定（`startQuarter`）

只在 `phase` 是 `"running"` 并且 `day % 90 === 0` 时可以调用。按顺序：

1. 季度统计清零。
2. **升级**（跨境直发并且 `upgradeToLocal` 是 `true`）：费用是 `localSetupFeeFen + Math.ceil(stockQty * weightG * headHaulFenPerKg / 1000)`。现金不够就不升级，发出"升级失败"事件。够的话：付钱；现有库存变成一批补货，`arriveDay = day + headHaulDays`，`stockQty` 变成 0；还在路上的补货 `arriveDay` 加 `headHaulDays`；`fulfillment` 变成 `"local"`；`riskPts = riskStartPts`。
3. **合规**：见第八节。
4. **大单报价**：见 7.2。按 `bulkQuotes` 的顺序处理。
5. 记下新的售价、广告出价、每日预算、每月补货量。

### 10.2 每一天（`stepDay`）

按下面的顺序做，顺序不能变。每一步发生的事都放进事件列表。

0. **检查大单的货**：见第十六节。如果需要玩家选择而还没有选，这一步之后立刻返回，后面的步骤都不做，`day` 不变。
1. **月初**（`day % 30 === 0`，只在 `"running"` 阶段）：
   1. 评分低于 `initialRatingE1` 时加 1。
   2. `cashFen -= monthlyFixedCostFen`。
   3. 仓储费（只对本土店，第 0 天不收）：按 10.3 算出 `storageFeeFen`，`cashFen -= storageFeeFen`。
   4. 用 `monthStats` 重新算推流分（第 0 天用"没有数据"那一列），然后把 `monthStats` 清零。
   5. 自动补货：件数取 `monthlyRestockQty`、`product.supplierMonthlyCap`、买得起的最大件数三者里最小的；结果低于起订量就改成 0。和玩家要的不一样时发出"补货被减少"事件。费用按 10.4 算。到货日：跨境直发是 `day + supplierLeadDays`；本土店是 `day + supplierLeadDays + headHaulDays`。
2. **到货**：`arriveDay === day` 的补货，件数加进库存。
3. **事件**：今天有安排好的运输延误或差评就执行。
4. **大单**：按 7.3，先处理今天要发货的，再处理今天交货的，再处理今天收尾款的。
5. **市场热度**：算 `demandBp` 和 `refBidFen`。
6. **零售订单**（只在 `"running"` 阶段）：算 `organicOrders`、`adSpendFen`、`adOrders`。`cashFen -= adSpendFen`。
7. **零售发货**（只在 `"running"` 阶段）：
   - `wanted = organicOrders + adOrders`
   - `shipped = Math.min(wanted, Math.max(0, stockQty - reservedQty))`，`lost = wanted - shipped`
   - `stockQty -= shipped`；`cashFen -= shipped * perOrderFeeFen`（跨境直发是货代费，本土店是贴单费）
   - `shipped > 0` 时记一个 `OrderBatch`。`payoutFenEach` 用 `settleOrder` 算：地区西马，没有达人，不参加返现活动。
   - 送达日：跨境直发是 `day + dayRng(seed, day, 4).int(crossDeliveryMinDays, crossDeliveryMaxDays)`；本土店是 `day + localDeliveryDays`。
   - 更新 `monthStats` 和 `quarterStats`。
8. **签收**：`deliverDay === day` 的订单批次。用 `dayRng(seed, orderDay, 5)`，这一批的每一单依次取 `int(0, 9999)`，小于 `product.returnBp` 就是退货。记下 `returnedQty`。`settleDay = day + crossSettleDays` 或 `day + localSettleDays`，按这一批自己的 `fulfillment`。
9. **到账**：`day >= payoutFrozenUntilDay` 时，所有 `settleDay !== null`、`settleDay <= day`、`paid` 是 `false` 的订单批次：`cashFen += (qty - returnedQty) * payoutFenEach`，标成已到账。
10. **季末**（`day % 90 === 89`，只在 `"running"` 阶段，只对本土店）：见第八节。
11. **检查**，按顺序：
    - `phase` 已经是 `"banned"`：结束。
    - `cashFen < 0`：`phase` 变成 `"bankrupt"`，结束。
    - `"running"` 阶段过完第 719 天：`phase` 变成 `"closing"`。
    - `"closing"` 阶段，所有订单批次都已到账，所有大单的 `status` 都是 `"paid"` 或 `"defaulted"`：`phase` 变成 `"finished"`。
12. `day` 加 1。

退货的规则（简化）：退货的那一单平台不打款，商品不回到库存，已经付的每单费用不退。

### 10.3 本土店的仓储费

按体积、按天收费，放得久的库存收得更贵。为了不用记每一件货的入库时间，用"上个月卖掉多少"来区分：

```
lastMonthUnits = monthStats.shipped + monthStats.bulkUnits     // 上个月零售和大单一共发出多少件
normalQty = Math.min(stockQty, lastMonthUnits)                 // 一个月之内卖得掉的部分
agedQty   = stockQty - normalQty                               // 卖不掉、压在仓库里的部分

normalSen = Math.ceil(normalQty * product.volumeCm3 * storageSenPerCbmDay     * 30 / 1000000)
agedSen   = Math.ceil(agedQty   * product.volumeCm3 * agedStorageSenPerCbmDay * 30 / 1000000)
storageFeeFen = senToFen(normalSen + agedSen, cnyPerRmE4)
```

跨境直发的货放在国内，这一版不收仓储费。

### 10.4 进货的价格：买得多更便宜

零售和大单用的是同一批货。一次进货的件数越多，每件越便宜：

```
multiple = Math.floor(qty / product.moq)
discountBp =
  multiple >= buyTier2Multiple -> buyTier2DiscountBp
  multiple >= buyTier1Multiple -> buyTier1DiscountBp
  其他                          -> 0
unitCostFen = applyBp(product.costFen, 10000 - discountBp)

进货费用 = qty * unitCostFen
本土店再加头程运费：Math.ceil(qty * weightG * headHaulFenPerKg / 1000)
```

开局的第一批货和每个月的自动补货都按这个算。"买得起的最大件数"按没有折扣的价格估算就行，实际付的钱按折扣后的算。

净资产里的库存仍然按 `product.costFen`（没有折扣的进价）算。

用 200 个不同的种子，每个种子用随机的合法决定跑完一局。6 种商品、两种开局方式、中途升级都要覆盖到。每一局都要满足：

1. **重放一致**：同样的 `config` 和决定再算一遍，最后的状态完全相同。
2. **现金对得上**：`cashFen === startCashFen - setupFeeFen - complianceFen - restockFen - adSpendFen - perOrderFeeFen - fixedCostFen - storageFen + payoutFen + bulkInFen - bulkOutFen`。
3. **库存对得上**：`stockQty === unitsBought - ordersShipped - bulkUnits - 还在路上的补货件数`。
4. `"finished"` 时：所有订单批次都已到账；所有大单的 `status` 是 `"paid"` 或 `"defaulted"`。
5. 库存、评分、信誉、风险值、各项累计数都不小于 0。每个月的推流分在 0 到 100 之间。
6. 每天结束时，除了 `"bankrupt"`，`cashFen` 不小于 0。
7. **运气和决定无关**：同一个种子、两组不同的决定，每一天的 `demandBp` 相同，事件日期和询价单完全相同。
8. **零售不动大单的货**：任何一天零售发货之后，`stockQty` 不小于 `reservedQty`，除非发货之前就已经小于。
9. **风控只影响本土店**：一直是跨境直发的局，没有 `audit_started` 和 `banned` 事件，`riskPts` 一直是 0。
10. 审核期间（`day < payoutFrozenUntilDay`）没有平台货款到账。

## 十五、季度中间的决定和账单的核对用例

加急补货，头巾（进价 900 分）：

| 缺的件数 | 发货方式 | 补多少件 | 每件（分） | 一共（分） | 几天到 |
|---|---|---|---|---|---|
| 96 | cross | 100 | 1080 | 108000 | 3 |
| 96 | local | 100 | 1260 | 126000 | 5 |

整局的关系（加进 14.6 的 200 局里一起检查）：

11. `pending` 不是 `null` 时调用 `stepDay`，状态不变。
12. 把一局里每个季度实际做过的选择填进 `bulkShortChoices` 再重放，最后的状态完全相同。
13. 每个季度：`verifyQuarter` 成立；账单的编号没有重复。

## 十六、季度中间的决定：大单的货不够

三个员工不会自己做任何决定。整局里只有这一种季度中间的决定，由玩家来选。

**什么时候检查**：`stepDay` 的第 0 步。对每一张 `status` 是 `"won"`、`warnDay === day`、并且 `midChoices` 里还没有记录的大单：

```
arrivals     = restockBatches 里 arriveDay <= shipDay 的件数之和
lead         = 跨境直发 supplierLeadDays；本土店 supplierLeadDays + headHaulDays
futureMonths = 满足 d % 30 === 0、day <= d <= 719、d + lead <= shipDay 的天数 d 的个数
futureQty    = futureMonths * Math.min(monthlyRestockQty, product.supplierMonthlyCap)
earlier      = 其他 status 是 "won"、shipDay 更早（或相同但排在前面）的大单的 qty 之和
projected    = stockQty + arrivals + futureQty - earlier
```

- `projected >= qty`：货够。发出 `bulk_on_track` 事件，`midChoices[inquiryId] = "none"`，继续。
- `projected < qty`：货不够。`pending = { kind: "bulk_short", inquiryId, shortQty: qty - projected }`，发出 `bulk_short` 事件，`stepDay` 立刻返回。

**玩家选了之后**（`answerPending`）：

| 选择 | 做什么 |
|---|---|
| `"rush"`（加急补货） | 件数是 `Math.ceil(shortQty / 10) * 10`。每件 `applyBp(product.costFen, 10000 + rushPremiumBp)`，溢价按现在的发货方式取。现金不够时抛出错误（界面上这个选项不能点）。付钱（记进 `totals.restockFen`，件数记进 `totals.unitsBought`），记一批 `rush` 是 `true` 的补货，`arriveDay = day + rushLeadDays`。不受供应商月上限的限制 |
| `"ignore"`（不处理） | 什么都不做。到发货那天货不够就违约 |

然后 `midChoices[inquiryId] = choice`，`pending = null`。再调用 `stepDay` 就会接着往下算。

试算（`docs/06` 的 `dryRunQuarter`）和没有给出选择的重放，一律当作 `"ignore"`。

## 十七、账单

每个季度结束时，把这个季度的事件整理成账单。玩家确认账单之后才能进入下一个季度（界面的规则见 `docs/09`）。

```ts
interface Bill {
  id: string;                 // 例如 "Q4-RST-02"：第 4 个季度、进货、第 2 笔
  day: number;
  role: "purchase" | "ops" | "finance";   // 哪个角色经手
  kind: string;               // 见下表
  amountFen: number;          // 收入是正数，支出是负数
  refId?: string;             // 对应的补货单或询价单的编号
  count?: number;             // 这一笔包含多少件、多少单或多少次点击
}
```

| `kind` | 编号里的代码 | 是什么 | 经手 | 怎么合并 |
|---|---|---|---|---|
| `restock` | `RST` | 进货（本土店含头程运费） | 采购 | 每张补货单一笔 |
| `rush` | `RSH` | 加急补货 | 采购 | 每次一笔 |
| `bulk_freight` | `FRT` | 大单的运费 | 采购 | 每张大单一笔 |
| `ads` | `ADS` | 广告费 | 运营 | 每个月合成一笔 |
| `order_fee` | `FEE` | 每单的货代费或贴单费 | 运营 | 每个月合成一笔 |
| `payout` | `PAY` | 平台回款 | 财务 | 每一批到账一笔 |
| `bulk_deposit` | `DEP` | 大单定金 | 财务 | 每张大单一笔 |
| `bulk_balance` | `BAL` | 大单尾款 | 财务 | 每张大单一笔 |
| `bulk_penalty` | `PEN` | 大单违约：退回的定金加违约金 | 财务 | 每张大单一笔 |
| `fixed` | `FIX` | 每月固定开支 | 财务 | 每个月一笔 |
| `storage` | `STO` | 仓储费 | 财务 | 每个月一笔 |
| `compliance` | `CMP` | 合规 | 财务 | 每次一笔 |
| `setup` | `SET` | 本土店开通费，含升级时搬库存的运费 | 财务 | 每次一笔 |

- 编号：`"Q" + (q + 1) + "-" + 代码 + "-" + 两位序号`。序号在同一个季度、同一种 `kind` 里从 01 开始，按日期排。
- 补货单的编号：`"R" + (q + 1) + "-" + 两位序号`，在下单那天生成。开局的第一批货是 `"R1-01"`，它和开通费都算第 1 个季度的账。
- 账单显示的中文名字放在 `src/text`，用 `kind` 对应。

```
verifyQuarter(startCashFen, bills, endCashFen)：
  startCashFen + 所有 bills 的 amountFen 之和 === endCashFen
```

第 1 个季度的 `startCashFen` 是 `config.startCashFen`（付开通费和第一批货之前）。之后每个季度是上个季度的 `endCashFen`。第 720 天之后收尾阶段发生的钱，算在第 8 个季度的账单里，序号接着往下排。

`carryOver(state)` 返回带到下个季度的四样：

| 内容 | 怎么取 |
|---|---|
| 路上的货款 | `paid` 是 `false` 的订单批次：批数，以及 `(qty - (returnedQty ?? 0)) * payoutFenEach` 之和。被冻结时带上解冻的日子 |
| 没结清的大单 | `status` 是 `"won"`、`"shipped"`、`"delivered"` 的大单 |
| 路上的补货 | 还没到货的补货单 |
| 留给大单的货 | `reservedQty` |

## 十八、这一版不做的

- 货到付款、达人带货、平台返现活动（`settleOrder` 支持，但游戏里不用）。
- 东马的订单（全部按西马算）。
- 一局里卖多种商品。
- 汇率变化。
- 退货的商品回到库存。
- 跨境直发在国内的仓储费、大单拖欠尾款、大单的质量扣款、大单的部分交货。
