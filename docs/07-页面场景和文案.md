# 07 页面和文案

这份文档规定游戏看起来是什么样、每个阶段画面上放什么、文字怎么写。

相关的文档：画面上的硬性限制见 `docs/08`；组件、弹窗和输入规则见 `docs/09`；世界和图形见 `docs/10`；界面的框架和体验设计见 `docs/12`。

## 一、设计方向

**一个看得见的小世界，三个站在前排的角色，一个往前走的时间线。**

- 画面的主体是一个世界：左上是中国的供应商，中间是海和货船，右下是马来西亚的仓库和买家。货从左往右走，钱沿着一条金色的线往回走。
- 三个角色（采购、运营、财务）站在世界的前面，每人旁边一个说话框。
- 整局游戏都在这一个画面上，不换页。变的只有：季度、季节的布置、世界里在动的东西、角色说的话、打开的弹窗。
- 风格：明亮、干净、像一个精致的小模型。界面的元素有粗的深色边框和底部的"厚度"，像可以按下去的实体按钮。

## 三、一个画面，六个阶段

| 阶段 | 世界 | 前排 | 底部 |
|---|---|---|---|
| 首页 | 慢慢地动 | 标题和"开始经营"盖在中间 | 页脚三句话 |
| 开局 | 静止，建筑是暗的；选了发货方式后亮起来 | 三步选择的卡片 | "开店" |
| 做决定 | 静止，显示这个季度的季节 | 三个角色和说话框 | 四组决定和"进入下一个季度" |
| 播放 | 动起来 | 三个角色，说话框收起，头顶冒出提醒 | "跳过" |
| 结算 | 静止 | 三个角色换成对账的表情 | "进入下一个季度"是灰的，直到确认账单 |
| 结局 | 定格，盖上结果的印章 | 结果、现金曲线、三个角色的统计 | "再来一局"等 |

## 四、布局（电脑 1440 × 800）

所有位置都是固定的，每个季度都一样。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [第一年 · 第四季度 年终大促 ●●●◉ ○○○○]      [现金] [库存] [推流分] [风险] [?] │ 16 到 60
│                                                             ┌──────────┐ │
│                                                             │ 询价单    │ │ 76 起
│                         世   界                             └──────────┘ │
│                                                                          │
│                                                                          │
│ (采购)[说话框]          (运营)[说话框]          (财务)[说话框]             │ 520 到 696
│ [进货]      [零售]      [大单]      [风险]      [ 进入下一个季度 ▶ ]        │ 714 到 784
└──────────────────────────────────────────────────────────────────────────┘
```

| 区 | 位置 | 内容 |
|---|---|---|
| 世界 | 铺满整个画面，在最下面一层 | three.js 的画布 |
| 时间线 | 左上 | 第几年、第几季度、季节的名字、8 个点（走过的、现在的、没到的） |
| 状态 | 右上 | 现金（数字最大）、库存、推流分、风险等级（只有本土店）、"?"（数字从哪来） |
| 询价 | 右上，状态的下面 | 这个季度的询价单。没有时不显示 |
| 前排 | 下方，三等分 | 每一格：左边是角色，右边是说话框 |
| 决定栏 | 最下面 | 四组决定各一格，加主要按钮。主要按钮永远在右下角 |

说话框固定 150 高，里面从上到下：

1. 第一行：角色的称呼；右边一个按钮（"全听他的"；选过之后显示"已选 · 进货听他的"这样的字）。
2. 两行：他说的话。
3. 两行：左边是项目，右边是数字（他最想强调的一项，和他的预测）。

决定栏的每一格：第一行是这一组的名字，右边一个小标签写"听采购的""听运营的""听财务的"或"自己定"；第二行是现在的值。点这一格，打开对应的弹窗。

**播放时**：说话框收起，前排只剩三个角色；谁有提醒，就在谁头顶冒出一个小牌子。右上的询价换成"第 37 天 / 90"和这个季度到现在的几个数（订单、缺货、广告花费、到账）。右下的主要按钮换成"跳过"（不是金色）。

**结算时**：播放结束后自动打开季度账单的弹窗（见 `docs/09`）。玩家点"确认账单"之后，弹窗关闭，说话框重新展开，里面换成每个人的对账（"他预测 820 单，全听他的实际 631 单"），右下的主要按钮亮起来。

**开局**：前排的位置换成三步选择：三张商品卡、两张发货方式卡、第一批进货的滑块。做完一步亮下一步。发货方式卡必须写出 `docs/04` 第 2.1 节表格里的全部六行。

**结局**：世界定格。画面中间偏左是结果的印章和净资产；右边一栏是现金曲线、"最关键的一个决定"、你和三个角色的统计；底部是"再来一局""保存结果卡片""同一局再试一次"。

- "最关键的一个决定"：把每个季度的决定分别换成三个角色各自的完整方案，后面的季度保持玩家原来的决定，整局重算。净资产变化最大的那个季度就是最关键的。

## 五、手机（390 × 844）

- 世界在最上面，占屏幕高度的三分之一。
- 时间线和状态各一行，叠在世界的上方。状态只留现金、库存、推流分，其余收进"更多"。
- 前排改成左右滑动，一次看一个角色和他的说话框。下面有三个小圆点表示现在看的是谁。
- 决定栏固定在底部，两行：上面一行是四组决定（只写名字和小标签），下面一行是主要按钮。
- 所有弹窗从底部升起，占满宽度，最高到屏幕的 85%。
- 没有左右滚动。按钮的点击区域不小于 44 × 44。

## 六、文案

### 6.1 语气

- 像一个做过几年跨境的朋友在讲话。短句，用平常的词。
- 不用感叹号，不说"恭喜""太棒了""加油"。
- 数字比形容词有用。写"缺货 18 单"，不写"缺货比较严重"。
- 按钮写清楚点了会发生什么："开工""全听他的""下一个季度""再来一局"。
- 三个员工说话有区别：采购说货和天数，运营说单量和对手，财务说现金和风险。每条不超过 30 个字。

### 6.2 员工理由的文字

对应 `docs/06` 第七节的编号。大括号里是数字。

| `key` | 文字 |
|---|---|
| `purchase_season_up` | 这个季度是旺季，需求是上个季度的 {ratio} 倍，要多备货。 |
| `purchase_stock_days` | 现在的库存只够卖 {days} 天。 |
| `purchase_bulk_cannot` | {qty} 件那张单交不出，到时候还差 {short} 件。 |
| `ops_push_low` | 推流分只有 {score}，降一点价，平台才肯给流量。 |
| `ops_rival_bid` | 对手出 {rival}，我们出 {ours} 才抢得到。 |
| `ops_grab_all` | 这个季度有 {count} 张大单，一共 {qty} 件，都该抢。 |
| `finance_cash_low` | 照{who}的方案，现金最低会掉到 {low}。 |
| `finance_risk` | 平台风险已经到"{level}"，这个季度该做合规了。 |
| `finance_balance_late` | 大单的尾款要交货后 {days} 天才到，先想好这段时间的钱。 |
| `plan_ends_game` | 说实话，照我这个方案，第 {day} 天店就撑不住了。 |

### 6.3 事件的文字

| 事件 | 文字 |
|---|---|
| `restock_arrived` | 补货 {qty} 件到了。 |
| `restock_reduced` | 想补 {wanted} 件，只补了 {actual} 件。{reason} |
| `event_delay` | 运输延误，路上的货晚 {days} 天到。 |
| `event_bad_review` | 收到一条差评，评分 {from} → {to}。 |
| `bulk_won` | 中标：{qty} 件，单价 {price}，收到定金 {deposit}。 |
| `bulk_lost` | 没中。对手报的是 {rival}。 |
| `bulk_shipped` | 大单发货 {qty} 件。 |
| `bulk_delivered` | 大单交货，尾款 {balance} 将在 {days} 天后到账。 |
| `bulk_defaulted` | 大单违约：货不够。退定金 {deposit}，赔 {penalty}。 |
| `audit_started` | 平台风控审核，货款冻结 {days} 天。 |
| `banned` | 店铺被封。没到账的货款只拿回一半。 |
| `upgraded` | 已升级成本土店。库存在运往马来西亚的路上，{days} 天后到。 |
| `upgrade_failed` | 钱不够，没能升级成本土店。 |
| `bankrupt` | 现金变成负数，店开不下去了。 |

`restock_reduced` 的 `{reason}` 有两种："供应商这个月最多给这么多。""现金不够。"

### 6.4 四种结局

| 结局 | 印章 | 一句话 |
|---|---|---|
| 倒闭 | 倒闭 | 订单不少，但钱回来得太慢。 |
| 被封店 | 封店 | 本土店赚得快，也倒得快。 |
| 活下来了 | 活下来了 | 店还在，离第一桶金还差 {gap}。 |
| 赚到第一桶金 | 第一桶金 | 两年，{start} 变成了 {end}。 |

### 6.5 必须如实写明的三句话

放在首页页脚和"数字从哪来"面板的最上面：

1. 本游戏的规则是简化过的，不等于真实平台。
2. 三个 AI 员工的方案由固定规则计算，游戏运行时没有调用任何大模型。
3. 标为"设计值"的数字不代表真实市场。

### 6.6 新手提示

只在第一个季度出现，一共三条，每条指向一个地方，点一下就消失：

1. 指向世界："货从中国坐船去马来西亚，钱沿着这条金色的线回来。钱回来得比货慢。"
2. 指向三个角色："三个人的建议不一样。点他说话框上的按钮，就是听他的。点他本人，可以看他手上的每一件事。"
3. 指向推流分："平台按这个分数给你流量。分数低，广告也不好使。"

### 6.7 提醒的文字

提醒显示在角色头顶的小牌子里，每条不超过 20 个字。

| 什么时候 | 谁 | 文字 |
|---|---|---|
| 做决定时，有大单这个季度要交 | 采购 | 第 {day} 天要交 {qty} 件大单。 |
| 做决定时，库存不够卖 15 天 | 采购 | 库存只够卖 {days} 天。 |
| 做决定时，这个季度有货款到账 | 财务 | 这个季度有 {amount} 货款会到。 |
| 做决定时，风险不是"低" | 财务 | 平台风险到"{level}"了。 |
| 播放时，`bulk_on_track` | 采购 | {qty} 件大单的货够了。 |
| 播放时，`bulk_short` | 采购 | {qty} 件大单还差 {short} 件。 |
| 播放时，`restock_arrived` | 采购 | {qty} 件货到了。 |
| 播放时，货款到账 | 财务 | 到账 {amount}。 |
| 播放时，现金低于 ¥500 | 财务 | 现金只剩 {cash}。 |
| 播放时，`event_bad_review` | 运营 | 收到一条差评。 |
| 播放时，这个月缺货 | 运营 | 没货了，丢了 {lost} 单。 |

### 6.8 大单货不够时的选择

标题："大单快要发货了，货不够"。说明："第 {day} 天要发 {qty} 件，到时候还差 {short} 件。怎么办由你决定。"

| 选项 | 文字 | 下面的小字 |
|---|---|---|
| 加急补货 | 加急补 {n} 件 | 每件 {price}，一共 {cost}，{days} 天到。 |
| 不处理 | 不处理 | 到时候交不出：退定金 {deposit}，赔 {penalty}。 |

现金不够时，"加急补货"是灰的，小字换成"现金不够。"

### 6.9 季度账单的文字

财务在弹窗打开前说："这个季度的账我核对完了，请过目。"

| `kind` | 名字 |
|---|---|
| `restock` | 进货 |
| `rush` | 加急补货 |
| `bulk_freight` | 大单运费 |
| `ads` | 广告费 |
| `order_fee` | 每单的货代费（本土店叫"贴单费"） |
| `payout` | 平台回款 |
| `bulk_deposit` | 大单定金 |
| `bulk_balance` | 大单尾款 |
| `bulk_penalty` | 大单违约 |
| `fixed` | 每月固定开支 |
| `storage` | 仓储费 |
| `compliance` | 合规 |
| `setup` | 本土店开通 |

账单的编号显示成"Q4-进货-02"这样（把代码换成上表的名字）。

核对那一行："季度初 {start} + 收入 {income} − 支出 {expense} = 季度末 {end}。共 {count} 笔，已核对。"

主要按钮是灰的时候，旁边的字："先确认这个季度的账单。"做决定时四组没选完："四组决定还没选完。"

### 6.10 工作台里每件事的状态

| 状态 | 文字 |
|---|---|
| 进行中 | 在路上、等签收、等到账、备货中 |
| 已完成 | 已到货、已到账、已交货、已结清 |
| 有问题 | 被减少、货不够、被冻结、缺货 |
| 被取消 | 没中标、违约 |
