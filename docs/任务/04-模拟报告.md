# 任务 04：模拟报告

开始之前先读：`AGENTS.md`、`docs/04-经营模型.md`。

任务 03 完成并提交之后，才做这个任务。

## 一、为什么做

`docs/04` 和 `docs/05` 里等级 C 的数值是设计值。要知道游戏难不难、哪种商品太强或太弱、本土店和跨境店平不平衡，只能大量模拟。这份报告用来调整数值。

## 二、要做的事

写一个脚本 `scripts/simulate.ts`，加一个命令 `npm run sim`。它只使用 `src/engine`、`src/params`、`src/products`（任务 05 之后可以再用 `src/plan`），把结果写到 `模拟报告.md`。

规则包第 2 版：自动补货不看现金，季末才结账（`docs/04` 第 3 版）。"激进"打法补到供应商上限，现金会很快变成负数，这是这种打法自己的结果。

### 1. 五种固定的打法

每个季度的决定按下面的规则自动生成：

| 名称 | 售价 | 广告出价 | 每日预算 | 每月补货量 | 大单 | 合规 |
|---|---|---|---|---|---|---|
| 保守 | 参考价 | 0 | 0 | 上个季度平均每月发出的件数 | 不报 | 风险到"中"就做 |
| 均衡 | 参考价 | 对手出价的 80% | ¥30 | 上个季度平均每月发出件数的 1.2 倍 | 件数不超过现有库存加一个月补货量时，按批发参考价报 | 风险到"中"就做 |
| 激进 | 最低价 | 对手出价的 130% | ¥150 | 供应商的上限 | 全部按批发参考价的 92% 报 | 从不做 |
| 只做大单 | 最高价 | 0 | 0 | 这个季度所有询价单的件数之和除以 3 | 全部按批发参考价的 95% 报 | 风险到"中"就做 |
| 随机 | 合法范围内随机 | 0 到对手出价的 2 倍 | ¥0 到 ¥200 | 0 到供应商上限 | 每张一半可能报，报价在批发参考价的 85% 到 110% 之间 | 一半可能做 |

- "发出的件数"包含零售和大单。第一个季度用 `organicPerDayMilli * 30 / 1000`。
- 补货件数低于起订量时，按起订量补。
- 第一批进货：保守和均衡用启动资金的 40%，激进用 70%，只做大单用 30%，随机在 30% 到 80% 之间。本土店先扣掉开通费，再按剩下的钱算比例。超过 `supplierMonthlyCap` 就按上限。
- 遇到大单货不够要选择的时候（`docs/04` 第十六节）：保守和均衡在现金够时选加急补货，否则不处理；激进和只做大单选不处理；随机一半一半。
- 随机打法的随机数用 `createRng`，种子固定，不能用 `Math.random`。

### 2. 三种店铺路线

| 名称 | 做法 |
|---|---|
| 一直跨境 | 开局跨境直发，从不升级 |
| 一直本土 | 开局本土店 |
| 第二年升级 | 开局跨境直发，第 4 个季度（第二年第一个季度）开始时升级 |

### 3. 跑多少局

6 种商品 × 3 种路线 × 5 种打法，每一种组合跑 300 个种子（种子 1 到 300）。

### 4. 报告的内容

每一种组合一行：

| 列 | 含义 |
|---|---|
| 四种结局各占多少 | 倒闭、被封店、活下来了、赚到第一桶金 |
| 净资产 | 最低、中位数、最高 |
| 现金最低点 | 中位数，以及出现在第几天 |
| 推流分 | 平均值；第一年平均和第二年平均 |
| 广告 | 平均每局花费；实际花费占预算的比例 |
| 零售 | 平均每局发出的单数、缺货的单数、退货的单数 |
| 大单 | 平均每局中标几张、按时交货几张、违约几张；大单的收入占总收入的比例 |
| 仓储费 | 平均每局付了多少（只有本土店） |
| 进货折扣 | 进货次数里，拿到 5% 折扣和 10% 折扣的各占多少 |
| 风险 | 被审核的局占多少；被封店的局平均在第几个季度被封（只有本土店） |
| 一局算完的天数 | 中位数（含收尾阶段） |

另外加一张小表，检查沙盘是否成立：对每种商品，取种子 1 到 20，同一个种子下五种打法的净资产是否互不相同。列出有多少个种子出现了两种打法结果完全一样的情况（正常应该是 0 或很少）。

报告最后写四段话：

1. 哪些组合几乎一定倒闭或被封店，哪些几乎一定达到目标。
2. 三种路线之间差距大不大。本土店是不是"长期赚得更多，但风险更高"。
3. 零售和大单，哪一条线更赚钱。有没有只做一条线就能赢的情况。
4. 你认为哪些数值最需要调整。只提建议，**不要自己改数值**。

## 三、完成的标准

- `npm run sim` 能在 5 分钟之内跑完。
- `模拟报告.md` 已生成并提交。报告里不写生成的时间和运行用了多久，这样同样的代码每次生成的内容完全一样。
- 自动检查加上 K8（`docs/13` 第 2.2 节）。`npm run check:full` 通过。
- 检查员的结论是通过（`docs/13` 第五节）。
