# 12 界面框架和体验设计

这份文档把界面这一块的框架定下来：用什么搭、文件怎么放、哪些部分是固定的、数据怎么流、体验按什么原则设计。

相关的文档：画面和文案见 `docs/07`；画面限制见 `docs/08`；组件、弹窗、输入规则见 `docs/09`；世界见 `docs/10`。

## 一、用什么搭（定下来，不再换）

| 用途 | 用什么 | 说明 |
|---|---|---|
| 界面 | React，函数组件 | |
| 样式 | Tailwind CSS | 设计变量写进 Tailwind 的主题里 |
| 状态 | Zustand | 整个界面只有一个 store |
| 世界 | three.js | 直接用 three.js，不用再包一层的库。只在 `src/scene/` 里用 |
| 界面上的动画 | Motion | 只用于 `docs/09` 第六节列出的几种 |
| 弹窗 | `@radix-ui/react-dialog` | 负责焦点、Esc、遮罩。本身没有样式 |
| 滑块 | `@radix-ui/react-slider` | 开局的第一批进货 |
| 指向某处的提示 | `@radix-ui/react-popover` | 新手提示、点数字看解释 |
| 拼类名 | `clsx` | |
| 数字字体 | `@fontsource/barlow-semi-condensed` | |
| 图标、角色、印章 | 自己画的 SVG | 不装图标库 |
| 截图检查 | Playwright | 只在开发时用 |

上面这些依赖都已经同意，不用再问。不用现成的整套界面组件库。

Tailwind 的使用规则：只用主题里定义过的值，不写任意值（例如 `p-[13px]`）；固定的尺寸（时间线的高度、前排的高度、弹窗的宽度）也定义成主题里的值。

## 二、文件怎么放

```
src/ui/
  app/
    App.tsx              入口
    Stage.tsx            唯一的画面骨架（见第三节）
    ErrorScreen.tsx
  stages/                每个阶段盖在世界上面的内容
    HomeLayer.tsx  SetupLayer.tsx  DecideLayer.tsx  PlayLayer.tsx  SettleLayer.tsx  EndingLayer.tsx
  popups/                9 个弹窗，每个一个文件
  components/
    base/                docs/09 第 3.1 节
    biz/                 docs/09 第 3.2 节（世界除外）
  store/
    store.ts  actions.ts  selectors.ts
  dev/
    Gallery.tsx  demoStates.ts  DebugPanel.tsx  selfcheck.ts（页面自检，见 docs/13 第四节）
  theme/
    tokens.ts            设计变量。唯一可以写颜色值的地方（世界的颜色也在这里）
src/scene/
  WorldCanvas.tsx        把 three.js 的画布接进 React
  world/                 镜头、光、每一样模型、四个季节、动画
  cast/                  三个角色的 SVG
  fallback/              不支持 3D 时的静态图
src/text/zh.ts           全部文字
```

`src/scene/world/` 里的代码不引用 React。`WorldCanvas.tsx` 只做三件事：创建画布、把 store 里的状态和当天的事件传给世界、组件卸载时释放资源。

## 三、固定的部分和变化的部分

整个游戏只有一个骨架 `Stage`，从首页到结局都是它：

```
Stage
 ├─ WorldCanvas          一直在，最下面一层
 ├─ WorldLabels          一直在
 ├─ Timeline、StatusBar  从"做决定"起一直在，位置不变
 ├─ 当前阶段的内容        HomeLayer / SetupLayer / DecideLayer / PlayLayer / SettleLayer / EndingLayer
 └─ 当前打开的弹窗        最多一个
```

| 一直不变的 | 每个阶段不同的 |
|---|---|
| 世界的位置和镜头 | 季节的布置、世界里在动的东西 |
| 时间线、状态的位置 | 上面的数字 |
| 三个角色的位置 | 表情、说话框里的内容、头顶的提醒 |
| 决定栏和主要按钮的位置 | 主要按钮上的字：进入下一个季度 / 跳过 / 看结果 |
| 每个弹窗出现的位置 | |

规则：

1. 阶段之间切换时，世界、时间线、状态、三个角色都不重新出现、不闪。只有说话框和右上角的内容换。
2. **主要按钮永远在右下角。** 全屏只有它是金色的。
3. 同一个功能的按钮永远在同一个位置。

每个阶段用哪些组件：

| 阶段 | 组件 |
|---|---|
| 首页 | 标题、`Button`（开始经营）、页脚三句话、最好成绩 |
| 开局 | 3 个 `ProductCard`、2 个 `FulfillmentCard`、`FirstStock`、`Button`（开店、返回） |
| 做决定 | `Timeline`、`StatusBar`、`InquiryNote`、3 个 `CastMember`（含 `SpeechBubble`、`ReminderChip`）、`DecisionBar`（含 4 个 `DecisionSlot` 和主要按钮）、`CoachMark` |
| 播放 | `Timeline`、`StatusBar`、`PlayStats`、3 个 `CastMember`（说话框收起，只有 `ReminderChip`）、`Button`（跳过） |
| 结算 | 同"做决定"，说话框里换成对账；自动打开季度账单的弹窗 |
| 结局 | `EndingPanel`（含 `Stamp`、`CashCurve`）、`ResultCard`、4 个 `Button` |

## 四、数据怎么流

```
玩家点了什么
   │
   ▼
actions.ts 里的一个动作  ──调用──▶  src/engine、src/staff（纯计算）
   │                                        │
   ▼                                        ▼
store 里的状态更新          ◀──────────  新的 GameState 和事件列表
   │
   ├──▶ selectors.ts 取出要显示的东西 ──▶ 界面的组件
   └──▶ WorldCanvas 把状态和当天的事件交给世界 ──▶ 世界自己决定怎么画
```

规则：

1. 组件不直接调用 `engine` 和 `staff`，只通过 `actions.ts`。
2. 组件不直接读整个 store，只通过 `selectors.ts`。
3. 组件里没有计算。
4. 世界不保存任何游戏数据。它每次都从传进来的状态重新决定画什么（`docs/10` 第五节）。
5. `actions.ts` 里的每个动作都有测试。

动作的清单：

| 动作 | 做什么 |
|---|---|
| `startNewGame()` | 生成种子，去开局 |
| `pickProduct(id)`、`pickFulfillment(f)`、`setFirstStock(qty)` | 开局的三步 |
| `openShop()` | 调用 `createGame`，算第 1 个季度的三份方案和提醒，去做决定 |
| `chooseAll(staff)` | 四组都听某个人的 |
| `chooseGroup(group, staff)`、`setCustom(group, value)` | 弹窗里点"就这样定"时调用 |
| `openPopup(name)`、`closePopup()`、`openDesk(role)` | 弹窗 |
| `startQuarterPlay()` | 拼出决定，调用 `startQuarter`，然后一天一天调用 `stepDay`，直到这个季度结束或者遇到 `pending` |
| `answerBulkShort(choice)` | 调用 `answerPending`，把选择记进这个季度的决定里，继续往下算 |
| `finishPlay()` | 算这个季度的账单和对账，去结算，打开季度账单 |
| `confirmBill()` | 账单核对成立时，把 `billConfirmed` 设为 `true` |
| `nextQuarter()` | 只在 `billConfirmed` 是 `true` 时有效。算下一个季度的方案和提醒，去做决定；或者去结局 |
| `retrySameSeed()` | 用同一个种子回到开局 |
| `nextCoach()` | 新手提示 |

播放的做法：`startQuarterPlay` 先把模型算到停下的地方（季度结束或 `pending`），得到每一天的事件；界面再用 6 秒把这些天播放出来。播放到 `pending` 那一天，停住，打开弹窗。

## 五、三个角色只提建议和提醒，决定都由玩家做

这是整个界面的总原则：

1. 角色提的方案，玩家不点就不生效。
2. 提醒只说明情况，不带任何自动的动作。
3. 模型里唯一会自动发生的事是每个月初按玩家定好的数量补货。这个数量是玩家定的。
4. 需要在季度中间做决定的只有一种情况（大单货不够），这时播放停下来，等玩家选。
5. 进入下一个季度之前，玩家要先确认财务核对过的账单。

## 六、体验设计

### 6.1 给谁用

最重要的一类玩家：第一次打开、没做过跨境电商、只打算花几分钟的人。所有的体验决定都以这类人为准。

| 时候 | 他在想什么 | 界面怎么回答 |
|---|---|---|
| 刚打开 | 这是什么？要我做什么？ | 一眼看到世界：货从这边去那边，钱回来。首页一句话 |
| 做决定时 | 我该选哪个？选了会怎样？ | 三个角色站在面前，各说一句理由，各给一个预测 |
| 播放时 | 现在发生了什么？ | 世界在动；谁有事，谁头顶冒出一句话 |
| 结算时 | 钱去哪了？为什么是这个结果？ | 财务的账单；最多 3 句"为什么"；三个人的预测和实际 |

### 6.2 七条原则

1. **先给建议，再让人选。** 任何时候都不让玩家面对一个空的输入框。
2. **最快的路只要点两下。** 点一个角色的"全听他的"，再点主要按钮，就能过一个季度。想细调的人再点决定栏。
3. **不同的地方最显眼。** 弹窗里三个角色的建议并排，不一样的数字加粗。
4. **世界和数字说同一件事。** 库存多，货箱就多。玩家不看数字也能感觉到大概。
5. **坏消息提前说。** 做决定时就提醒；点主要按钮之前，提示还在。
6. **钱要说得清。** 每个季度一张账单，每一笔有编号，加起来对得上。
7. **可以重来。** 同一局再试一次，运气完全一样，只换决定。

### 6.3 节奏

| 阶段 | 大概用多久 |
|---|---|
| 首页 | 10 秒 |
| 开局 | 40 秒 |
| 做决定 | 第一个季度 40 秒，之后每个 15 到 25 秒 |
| 播放 | 6 秒，可以跳过；遇到大单货不够会停下 |
| 结算 | 10 到 15 秒 |
| 结局 | 30 秒 |

让做决定越来越快的办法：

1. **沿用上个季度的选择。** 从第二个季度起，每一组默认听上个季度听的那个人（用他这个季度的新数字），决定栏的小标签前面加"沿用"两个字。上个季度自己定的那一组，沿用自己定的值。第一个季度什么都不默认。
2. **一键全听。** 每个说话框上有"全听他的"。
3. **键盘。** 1、2、3 等于全听采购、运营、财务；回车等于点主要按钮。

### 6.4 一点一点地教

| 什么时候 | 出现什么 |
|---|---|
| 第 1 个季度 | 决定栏只有"进货"和"零售"两格是亮的，"大单"和"风险"写着"以后会用到"。三条新手提示（`docs/07` 第 6.6 节） |
| 第 2 个季度 | 第一次出现询价单。询价旁边一句："有批发客户来询价。报的价不高于对手就能拿下，但货要留给他。" |
| 第一次变成本土店 | 状态里出现风险等级。旁边一句："本土店有平台风控。等级到'高'会被审核。" |
| 第一次结算 | 账单弹窗的上方一句："每个季度结束，财务会把账核对好。你确认之后才能往下走。" |

**账单里的"为什么"**：最多 3 句话，把结果和原因连起来。按下面的顺序检查，条件成立就显示，满 3 句为止。计算放在 `src/staff/`，输出编号和数字，要有测试。

| `key` | 条件 | 文字 |
|---|---|---|
| `cause_bulk_default` | 这个季度有大单违约 | 大单交不出货，赔了 {penalty}。 |
| `cause_audit` | 这个季度末被审核 | 风险到了"高"，平台冻结货款 {days} 天。 |
| `cause_rush` | 这个季度加急补过货 | 加急补了 {qty} 件，比平时多花 {extra}。 |
| `cause_stockout` | 这个季度缺货超过 5% | 缺货 {lost} 单，"近期发货水平"掉了 {pts} 分，下个月平台给的流量会变少。 |
| `cause_bulk_reserved` | 有货留给了大单，并且零售有缺货 | 有 {qty} 件货留给了大单，零售不够卖。 |
| `cause_ads_unspent` | 广告实际花费不到预算的 60% | 广告预算只花掉 {pct}。出价比对手低，抢不到更多流量。 |
| `cause_ads_loss` | 每单的广告费高于每单的利润 | 广告每带来一单要花 {cost}，这一单只赚 {profit}。 |
| `cause_price_low` | 售价低于参考价 | 降价让"价格"多了 {pts} 分，但每单少赚 {diff}。 |
| `cause_price_high` | 售价高于参考价 | 涨价让每单多赚 {diff}，但"价格"少了 {pts} 分，买的人也少了。 |
| `cause_storage` | 本土店，仓储费里压货的部分大于 0 | 仓库里压着 {qty} 件卖不动的货，仓储费 {fee}。 |
| `cause_cash_wait` | 季度末路上的货款大于现金 | 账上有 {cash}，还有 {pending} 在路上没到。 |
| `cause_push_up` | 推流分比上个季度高 5 分以上 | 推流分涨到 {score}，不花广告费的订单会变多。 |

### 6.5 点数字看解释

可以点的数字下面有一条虚线。点了之后旁边弹出一句话，再点别处关闭。

| 数字 | 解释 |
|---|---|
| 对手出价 | 同类店铺平均出这个价。你的出价不到它的一半，就抢不到流量。 |
| 角色的预测 | 这是他自己的估计。上个季度他估了 {forecast}，全听他的实际是 {actual}。 |
| 路上的货款 | 货已经发出，平台还没打款。跨境直发签收后等 15 天，本土店等 7 天。 |
| 批发参考价 | 市场上这种货的普通批发价。对手的报价在它上下一成之内。 |
| 每件进价 | 一次进货达到 {tier1} 件便宜 5%，达到 {tier2} 件便宜 10%。 |

推流分和风险等级不用这个，它们有自己的弹窗和工作台。

### 6.6 防止出错

| 可能出的错 | 怎么防 |
|---|---|
| 没看方案就往下走 | 第一个季度四组都没有默认值，不选不能点主要按钮 |
| 输错数字 | 输入有范围，出错时说明原因；点"就这样定"才生效，"取消"不改任何东西 |
| 不知道会花多少钱 | 主要按钮下面一直显示"预计花掉" |
| 没看账单就往下走 | 不确认账单，主要按钮是灰的 |
| 弹窗关不掉 | 三种关法；自动检查每一个弹窗 |
| 看不懂为什么输了 | 结局的"最关键的一个决定" |

### 6.7 不做的

- 不做教程关卡，不做必须点完的说明页。
- 不做成就、等级、签到、每日任务。
- 除了"大单货不够"和季度账单，不做任何自己弹出来打断操作的东西。
- 不催玩家，没有倒计时。
