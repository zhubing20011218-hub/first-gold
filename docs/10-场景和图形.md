# 10 世界和图形

> 第 2 版（2026-11-20）：去掉三个角色。前排是三个功能区，用普通的网页元素做（见 `docs/07` 第四节）。

这份文档规定：游戏里的世界长什么样、怎么做、怎么跟着数据变。参考的画面在 `参考图/` 里，先读 `参考图/说明.md`。

## 一、做法

| 部分 | 用什么做 |
|---|---|
| 世界（地、海、建筑、船、车、树、买家） | three.js，画在一块画布上 |
| 三个功能区的小图标（一个纸箱、一个手机、一个计算器） | 自己画的 SVG |
| 图标、印章、小牌子 | SVG 和普通的网页元素 |
| 所有文字 | 普通的网页元素。**文字不放进 3D 里** |

- 模型全部在代码里用基本形状拼出来：方块、圆柱、圆锥、棱柱、球。不加载外部的模型文件和贴图。
- 世界从首页到结局是同一个，镜头固定。只有季节的布置、会动的东西、亮和暗在变。
- 代码放在 `src/scene/`。每一样东西是一个函数，返回一个 three.js 的组。

## 五、世界怎么跟着数据变

世界里的每一样东西都只从模型的状态和事件算出来，不另外保存。

| 数据 | 世界里的表现 |
|---|---|
| 发货方式是跨境直发 | 仓库是暗的（颜色变灰），卷帘门关着，门口没有货箱。货箱堆在工厂门口 |
| 发货方式是本土店 | 仓库正常颜色，卷帘门开着，货箱堆在仓库门口 |
| 库存 | 门口货箱的数量分四档：0 件没有；不够卖 7 天是 1 个；不够卖 30 天是 3 个；更多是 6 个 |
| 路上的补货（本土店）、路上的货（跨境直发） | 船上集装箱的数量：没有、3 个、7 个三档。船沿着货的去路走 |
| 当天发出的零售订单 | 货车在路上走；买家手里拿包裹的人数 |
| 大单发货 | 一辆满载的货车或一条满载的船，上面的集装箱是金色的 |
| 路上的货款 | 钱的回路上金币的数量，最多 6 个 |
| 货款到账 | 一枚金币走到中国那一端，消失 |
| 缺货 | 货箱堆的位置空着，上方出现红色的"缺货"牌子 |
| 平台审核 | 金币停住并变灰；仓库上方出现"审核"的印章 |
| 封店 | 马来西亚整块变灰，仓库门口出现"封店"的印章，一切停住 |
| 倒闭 | 整个世界变灰，中间出现"倒闭"的印章 |
| 差评 | 一栋房子上方冒出一个红色的小牌子，2 秒后消失 |
| 运输延误 | 船或货车停 1 秒再走 |

世界里的小牌子（"中国 · 供应商""马来西亚 · 仓库""买家""路上的货 86 件""路上的货款 ¥2,140.00""库存 320 件"）是网页元素，位置由 3D 里的点换算到屏幕上。它们互相不能重叠，也不能盖住前排的三个功能区。

## 六、动画

| 什么 | 怎么动 | 什么时候 |
|---|---|---|
| 船 | 沿着货的去路匀速走；上下轻轻起伏 | 播放时走；其他时候只起伏 |
| 货车 | 沿着路匀速走 | 播放时 |
| 金币 | 沿着钱的回路匀速走；自己慢慢转 | 播放时走；其他时候只转 |
| 烟 | 烟囱口的几个白球慢慢上升变淡 | 一直 |
| 雪花 | 慢慢落下 | 冬天 |
| 棕榈树 | 叶子轻轻摆动 | 一直 |
| 买家 | 不走动。播放时每隔一会儿换一批位置 | 播放时 |

- 一个季度播放 6 秒，对应 90 天。船和金币在路上走的时间按真实的天数算（跨境直发的货慢、钱更慢；本土店都快）。
- 没有东西在走的时候（做决定、看账单），画布每秒只重画 12 次，省电。
- 系统开启"减少动态效果"时：什么都不动，只换数量和小牌子。

## 七、不支持 3D 的时候

打开页面时检测浏览器能不能用 WebGL。不能用，或者画布创建失败：

- 世界区显示一张静态的 SVG 图：两块地、海、三个地点的简单图形和名字。
- 小牌子上的数字照常更新。
- 游戏的其他部分完全照常。不弹出报错。

## 八、印章

组件 `Stamp`。一个圆角矩形的框，3 像素的边，里面是最粗的字，整体顺时针转 6 度。边和字同一个颜色，没有填色。

| 文字 | 颜色 |
|---|---|
| 中标、已交货、已核对、第一桶金 | `goldText` |
| 活下来了 | `sea` |
| 没中、违约、审核、封店、倒闭、对不上 | `hibiscus` |

## 九、纪念海报

> 第 4 版（2026-11-20）：calmness 要求把"结果卡片"做成一张纪念海报，按玩家最后的收入画。

结局时生成一张海报，玩家点"保存纪念海报"存成图片。1080 × 1350（竖的，适合发朋友圈和小红书一类的地方，但图上不出现任何平台的名字），用 2D 的 Canvas 画，颜色全部来自 `src/ui/theme/tokens.ts`，不用图片文件，不发网络请求。

**主角是一只桶。** "第一桶金"就是一桶金子：桶里装了多少，按玩家的净资产占目标（`goalNetWorthFen`）的比例来画。

```
fillBp   = clamp(Math.floor(netWorthFen * 10000 / goalNetWorthFen), 0, 10000)   // 桶里金子的高度
overflow = clamp(Math.floor((netWorthFen - goalNetWorthFen) * 10 / goalNetWorthFen), 0, 12)   // 从桶口溢出来的金币个数
multiple = Math.floor(netWorthFen * 10 / goalNetWorthFen)   // 是目标的几倍，一位小数显示（例如 1.6 倍）
```

| 结局 | 桶的样子 | 大字 | 印章 |
|---|---|---|---|
| 赚到第一桶金 | 装满，金币按 `overflow` 从桶口溢出来，桶边有几道亮光 | 第一桶金 | 第一桶金（`goldText`） |
| 活下来了 | 金子装到 `fillBp` 的高度，桶口上方一条虚线标出"目标" | 离第一桶金还差 {gap} | 活下来了（`sea`） |
| 倒闭 | 空桶，桶身一道裂缝，整张图偏灰 | 季末付不起 | 倒闭（`hibiscus`） |
| 被封店 | 桶里的金子装到 `fillBp`，桶口贴着一张封条 | 店被封了 | 封店（`hibiscus`） |

从上到下：

1. 标题"第一桶金"，下面一行小字：卖的商品和发货方式（例如"头巾 · 本土店"）。
2. 桶（占整张图大约 45% 的高度），印章斜盖在桶的右上角。
3. 大字（上表），下面是净资产，最大的数字；再下面一行："{start} → {end}"，赚到第一桶金时后面加"（目标的 {multiple} 倍）"。
4. 两年的现金曲线，一条细线，标出最低点。
5. 三个数：零售一共卖了多少单、大单交了几张、最关键的那个季度（`docs/06` 第八节）。
6. 最下面一行小字：种子编号，和"规则是简化过的，不等于真实平台。"

海报上只写事实和数字，不写"恭喜""太棒了"（`docs/07` 第 6.1 节）。画海报的函数只接收算好的数字（结局、净资产、目标、现金曲线、三个数、商品、发货方式、种子），自己不做游戏里的计算；`fillBp`、`overflow`、`multiple` 放在 `src/plan/`，要有测试。
