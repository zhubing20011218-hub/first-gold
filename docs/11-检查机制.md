# 11 检查机制

> 第 2 版（2026-11-20）：`src/staff` 改名 `src/plan`；去掉和三个员工有关的检查。

这份文档规定：怎样确认做出来的东西是对的。每个任务做完都要过这里的检查，不通过不进入下一个任务。

这些检查怎样自动发生、由谁下结论，见 `docs/13-检查员.md`。

## 一、四道检查

| 检查 | 查什么 | 谁来做 | 什么时候 |
|---|---|---|---|
| 自动测试 | 钱算得对不对、规则有没有被破坏 | 程序（`npm run test`） | 每次改代码之后 |
| 模拟 | 数值合不合理、沙盘是否成立 | 程序（`npm run sim`） | 模型或数值改了之后 |
| 画面检查 | 每一屏在每种屏幕上对不对 | 程序（`npm run shots`）加人看截图 | 界面改了之后 |
| 试玩 | 看不看得懂、好不好玩 | 人 | 界面的任务做完之后 |

## 二、自动测试

### 2.1 测试分五类

| 类别 | 内容 | 写在哪 |
|---|---|---|
| 核对用例 | 文档里给出的数字，逐条算对 | `docs/03` 第十节、`docs/04` 第十四节、`docs/05` 第四节、`docs/06` 第十节 |
| 整局的关系 | 现金、库存、订单对得上；重放结果相同 | `docs/04` 第 14.6 节 |
| 边界 | 不合法的输入会报错；现金不够、货不够时的处理 | 各任务文件 |
| 规则检查 | 用程序读源代码，查有没有违反约定 | 下面 2.2 |
| 界面逻辑 | `actions.ts` 里每个动作的状态变化：三个功能区定了没有、沿用上个季度、主要按钮什么时候能点、没确认报表不能进入下一个季度、播放遇到 `pending` 会停下 | `docs/09` 第一节、`docs/12` 第四节 |

### 2.2 规则检查

一个测试文件，读取源代码的文字来检查。任务 01 先做前两条，其余的在出现对应代码的任务里加上。

| 编号 | 检查 | 范围 |
|---|---|---|
| R1 | 没有 `Math.random`、`Date.now`、`new Date` | `src/engine`、`src/plan` |
| R2 | 没有引用 `ui`、`scene`、`text`、`react` | `src/engine`、`src/plan`（`plan` 可以引用 `engine`） |
| R3 | 没有 `fetch(`、`XMLHttpRequest`、`WebSocket`、`sendBeacon` | 整个 `src` |
| R4 | 没有直接写的颜色值（`#` 加 3、4、6、8 位十六进制，`rgb(`、`hsl(`） | `src/ui`、`src/scene` 里的代码和 `.css` 文件。只有两处例外：`src/ui/theme/tokens.ts`；`src/ui/theme/theme.css` 的 `@theme` 里 `--color-` 开头的变量（Tailwind 4 的主题只能写在 CSS 里），这些变量要有测试核对和 `tokens.ts` 一样。`theme.css` 其他地方用 `var(--color-…)` |
| R5 | 字符串里没有中文 | `src/ui`、`src/scene`、`src/engine`、`src/plan`（注释里可以有） |
| R6 | 没有真实平台和聊天软件的名字 | 整个 `src`。名单放在测试文件里 |
| R7 | 没有 `any` 和 `@ts-ignore` | 整个 `src` |
| R8 | 参数表里每个参数都有 `value`、`unit`、`source`、`note`、`public`，`source` 只能是 A、B、C | `src/params` |
| R9 | 类名里没有 Tailwind 的任意值（`-[` 这种写法） | `src/ui`、`src/scene` |
| R10 | 没有直接引用 `engine` 和 `plan`（只能通过 `store/actions.ts` 和 `store/selectors.ts`） | `src/ui/stages`、`src/ui/popups`、`src/ui/components`（`docs/12` 第二节的文件结构） |

### 2.3 测试不能做的事

- 不能为了通过而改核对用例里的数字。
- 不能跳过测试（不用 `skip`、`only`）。
- 不能把出错的情况包起来假装没出错。

## 三、模拟

见任务 04。每次改了 `docs/04`、`docs/05`、`docs/06` 里的数值，都要重新运行，并把新的 `模拟报告.md` 提交。

模拟报告要回答的问题：

1. 有没有必赢或必输的打法。
2. 六种商品、三种店铺路线之间差距是否合理。
3. 零售和大单是不是都有用。
4. 同一个种子下，不同的打法结果是否不同。
5. 季末结账（`docs/06` 第四节）之后：没有一种固定打法（打法加店铺路线）在所有商品上都稳赢；"一开局就倒闭"（第一个季度结束时就付不起）只出现在玩家自己把钱花过了头的打法里。

## 四、画面检查

### 4.1 自动截图

脚本 `scripts/shots.ts`，命令 `npm run shots`。用 Playwright 打开本地预览，依次进入 `docs/09` 第九节的每一个 `?demo=` 页面和 `?gallery=1`，在下面几种窗口大小下截图：

| 窗口 | 用途 |
|---|---|
| 1440 × 800 | 电脑的设计基准 |
| 1440 × 680 | 电脑上比较矮的窗口 |
| 1280 × 720 | 常见的笔记本 |
| 1024 × 768 | 电脑布局的下限（平板横放、窄窗口） |
| 1920 × 1080 | 电脑的上限 |
| 390 × 844 | 手机 |
| 360 × 780 | 手机的下限（`docs/08` 第一节，360 到 430） |

截图存到 `过程截图/自动/`，文件名是"名字-宽x高.png"。Playwright 只是开发时用的工具，不会进入发布的网站。

截完之后再生成一个网页 `过程截图/自动/对照.html`，左边是 `参考图/` 里的图，右边是对应的实际截图，给人对照着看。哪张对哪张见 `docs/13` 第七节。

截图之前要等世界的画布画完（页面在画完第一帧后把一个标记设为完成，脚本等这个标记；等不到算 S10 不通过）。世界的部分不做逐个像素的比对。截图时打开"减少动态效果"，世界里什么都不动，每次截出来都一样。

`过程截图/自动/` 每次 `check:full` 都会重新生成，不提交进 git（写进 `.gitignore`）。要留下来给人看的截图，另外放在 `过程截图/` 下面别的文件夹里。

### 4.2 截图的同时自动检查

每一屏、每种窗口都检查下面这些，不通过就报错：

| 编号 | 检查 |
|---|---|
| S1 | 没有左右滚动，也没有东西跑出窗口：每一个看得见的元素，左边不小于 0、右边不大于窗口宽（弹窗打开时只查弹窗。弹窗指 `docs/09` 第四节的 P1 到 P9，新手提示和点数字弹出的解释不算弹窗）；页面和每个可以滚动的区域都没有左右滚动（`scrollWidth` 不大于 `clientWidth`） |
| S2 | 1440 × 800 时没有上下滚动 |
| S3 | 没有小于 12 像素的文字（包括输入框里的字、`::before`/`::after` 里的字，和 SVG 里的字：字号乘以 SVG 的缩放比例，不小于 12） |
| S4 | 可以点的东西（按钮、输入框、链接、页签、滑块、下拉框、多行输入框、`role` 是 button、radio、tab、slider 的元素）的点击区域：用手机的布局时（窗口宽小于 1024）不小于 44 × 44，其他时候不小于 32 × 32（`docs/08` 第十节）。例外：点数字看解释的链接（`Explain`）是文字里的链接，电脑上不受 32 × 32 限制（不然会撑乱功能区一行 22 高的字），手机上照样要 44 × 44 |
| S5 | 浏览器控制台没有报错 |
| S6 | 页面加载完成之后没有任何网络请求 |
| S7 | 没有文字被截断或互相重叠：每个文字元素（包括行内的金额、数字）的内容宽度不大于它自己的宽度；不被上层会切掉内容的框切掉；功能区和五个区（`docs/13` 第四节带 `data-region` 的区）里的每个元素上下左右都不超出它的上一层，功能区里的也不超出卡片的内边距；不被同一个功能区（或同一块）里的按钮盖住 |
| S8 | 所有图片和图形都有文字说明，或者标明是装饰 |
| S9 | 每个弹窗（`docs/09` 第四节的 P1 到 P9）：点对应的按钮能打开；弹窗完整地在屏幕之内；点叉、点外面、按 Esc 三种方式都能关上（P9 除外，它必须选一项） |
| S10 | 世界的画布不是空的（中间取几个点，颜色不全相同）；关掉 WebGL 再打开页面（1440 × 800、1920 × 1080、390 × 844、360 × 780），能看到静态的替代图，地点的名字对准图上的地点，不报错，并且能玩完一个季度；能用 WebGL 时不能退成替代图 |
| S11 | 用最长的内容再检查一遍 S7：现金 -¥99,999.00、最长的提醒、最长的参考数字、两张询价单、最长的决定值"RM 19.90 · ¥0.34 · ¥130" |
| S12 | 世界里的小牌子互相不重叠，也不盖住三个功能区 |
| S13 | 时间线、状态、询价、前排、底部这五个区互相不重叠（`docs/08` 第二节） |
| S14 | 画面上只有一个主要按钮（`docs/08` 第七节第 1 条）。弹窗打开时，弹窗后面的不算 |

S1、S3、S4、S7、S12、S13、S14 写在 `src/ui/dev/selfcheck.ts` 里，截图脚本和 `?debug=1` 的面板共用同一份，见 `docs/13` 第四节。

### 4.3 人看截图

自动检查发现不了"不好看"和"看不懂"。每次界面任务做完，人要把 `过程截图/自动/` 里的图看一遍，对照下面的清单：

- 和 `docs/07` 第四节的布局一样吗？打开 `过程截图/自动/对照.html`，和参考图是同一种感觉吗？
- 世界里的东西和数字对得上吗？（库存多，货箱就多；本土店，仓库是亮的）
- 四个季节一眼分得出来吗？
- 一眼能看出这一屏最重要的是什么吗？
- 三个功能区里，要点的按钮一眼找得到吗？现金计划看得懂吗？
- 数字都右对齐、小数位都一样吗？
- 有没有哪里红色太多？
- 手机上有没有哪一块挤在一起？

### 4.4 数字核对

在网址后面加 `?debug=1`，页面角落显示一个小面板，实时显示 `docs/04` 第 14.6 节第 2 条的现金等式：左边是现在的现金，右边是按累计数算出来的现金。两边不相等时面板变红。面板里还有一行页面自检的结果（`docs/13` 第四节）。这个面板只给开发用。

## 五、试玩

界面的任务（06、07、08）做完后，人要完整地玩。至少三局：

| 局 | 怎么玩 |
|---|---|
| 第一局 | 跨境直发，每个季度认真看参考数字和现金计划再决定 |
| 第二局 | 本土店，故意不做合规，看会不会被封店 |
| 第三局 | 跨境直发开局，中途升级；每张大单都抢，故意少进货，看会不会停下来问你 |

每一局记下：

1. 哪一步不知道该点哪里。
2. 哪个数字看不懂它是什么意思。
3. 哪个结果觉得不合理。
4. 一局用了多久。
5. 想不想再玩一局，为什么。

找别人试玩时，不要解释，只看对方在哪里停下来。

## 六、问题分三级

| 级别 | 是什么 | 怎么处理 |
|---|---|---|
| 一级 | 钱算错了；页面打不开或出错；公开链接不能访问；游戏里出现真实平台的名字 | 立刻修，修好之前不做别的 |
| 二级 | 流程走不通；某一屏在某种屏幕上错位；文字看不懂；核对不上的数字 | 这个任务结束之前修好 |
| 三级 | 不够好看；动画不够顺；文字可以更好 | 记下来，任务 09 一起处理 |

## 七、每个任务怎样才算完成

所有任务都要满足：

1. `npm run check:full` 通过（里面包括类型检查、全部测试、规则检查、核对用例齐全、打包和体积）。
2. 任务文件里"完成的标准"每一条都满足。
3. 没有一级和二级的问题。
4. `开发日志.md` 里有记录，git 已经提交。
5. **检查员的结论是通过**，检查记录在 `检查记录/` 里（`docs/13` 第五节）。
6. 任务文件最后要求报告的内容，已经如实报告。

界面的任务（06 到 09）再加：

7. 截图和 `对照.html` 已经更新（`npm run shots` 包含在 `check:full` 里）。
8. 已经重新发布，公开链接能打开。
9. 项目负责人看过截图；或者他说过不用看，开发日志里写明了，由写代码的助手自己对照文档和参考图看过。

## 八、发布之前的最后检查

见任务 09 的清单。全部通过之后才算可以提交作品。

| 谁 | 检查什么 |

| AI 编程助手 | 写代码；运行自动检查、模拟、截图；如实报告结果；列出文档里不清楚的地方 |
