# 09 UI 系统

> 第 2 版（2026-11-20）：去掉三个 AI 员工的方案。决定放在三个功能区里，由玩家自己定；底部是现金计划；季度报表付不起时只能申请破产。

这份文档规定：一局怎么往前走、界面由哪些组件拼成、9 个弹窗、每个输入框的规则。画面的样子见 `docs/07`，画面限制见 `docs/08`，世界见 `docs/10`，框架和体验见 `docs/12`，参考数字和现金计划见 `docs/06`。

## 一、一局怎么往前走

整个游戏是一个页面、一个画面。现在在哪个阶段，存在 store 里。

| 现在在 | 发生什么 | 去哪 | 条件 |
|---|---|---|---|
| 首页 | 点"开始经营" | 开局 | |
| 开局 | 点"开店" | 做决定（第 1 个季度） | 三步都选好，钱够付 |
| 开局 | 点"返回" | 首页 | |
| 做决定 | 点"进入下一个季度" | 播放 | 三个功能区都定好了，值都合法。**现金计划是负数不拦** |
| 播放 | 模型返回 `pending` | 播放暂停，打开"大单货不够"的弹窗 | |
| 播放（暂停） | 玩家选了 | 继续播放 | |
| 播放 | 播完，或点"跳过" | 结算 | 跳过时如果遇到 `pending`，仍然要停下来让玩家选 |
| 结算 | 点"确认报表" | 结算（已确认） | 报表核对成立，结论是 `continue` |
| 结算 | 点"申请破产" | 结局 | 结论是 `bankrupt`（季末现金小于 0）。这时报表里只有这一个按钮 |
| 结算 | 点"看结果" | 结局 | 结论是 `banned` 或 `finished` |
| 结算（已确认） | 点"进入下一个季度" | 做决定（下一个季度） | |
| 结局 | 点"再来一局" | 首页 | |
| 结局 | 点"同一局再试一次" | 开局（种子不变，选择保留，可以改） | |

- **没有确认报表，就不能进入下一个季度。** 这时主要按钮是灰的，旁边写着原因。
- 第 8 个季度结束后的收尾阶段（等货款到账）接在最后一次播放的后面，报表里单独列一段"收尾"。
- 做过的决定不能改。没有"返回上一个季度"。
- 刷新页面回到首页。这一版不保存进行到一半的局。

## 二、store 里存什么

```ts
type Area = "purchase" | "ops" | "finance";   // 进货、运营、财务（docs/06 第一节）

interface UiState {
  stage: "home" | "setup" | "decide" | "play" | "settle" | "ending";
  setup: { productId: string | null; fulfillment: "cross" | "local" | null; firstStockQty: number };
  seed: number;
  game: GameState | null;
  decision: QuarterDecision;             // 这个季度正在定的决定
  confirmed: Record<Area, boolean>;      // 三个功能区这个季度定了没有
  carried: Record<Area, boolean>;        // 是不是沿用上个季度的
  plan: CashPlan | null;                 // 季度开始时的现金计划（docs/06 第三节），结算时用来对比
  decisions: QuarterDecision[];          // 已经做过的每个季度的决定（含季度中间的选择）
  events: GameEvent[];                   // 整局到现在的事件
  quarterEvents: GameEvent[][];          // 这个季度每一天的事件
  quarterStartCashFen: number;
  bills: Bill[][];                       // 每个季度的账单
  billConfirmed: boolean;                // 这个季度的报表确认了没有
  history: QuarterSummary[];             // 每个季度的计划和实际
  reminders: Reminder[];                 // 这个季度出现过的提醒
  popup: null | "stock" | "retail" | "bulk" | "risk" | "push" | "bill" | "source" | "desk" | "bulkShort";
  deskArea: Area;
  playDay: number;                       // 播放到第几天
  coachStep: 0 | 1 | 2 | 3;
}
```

- store 只调用 `engine` 和 `plan` 的函数，自己不做任何计算。
- 同一时间只能开一个弹窗，所以 `popup` 只有一个值。
- 种子在点"开始经营"时用 `crypto.getRandomValues` 生成。这是整个项目里唯一允许的非确定性来源，只能出现在 `src/ui`。

## 四、9 个弹窗

位置固定。同一时间只开一个。

| 编号 | 弹窗 | 从哪里打开 | 出现在哪 | 宽 |
|---|---|---|---|---|
| P1 | 进货 | 进货区的"改" | 正中偏下，前排的正上方 | 560 |
| P2 | 零售 | 运营区"零售"的"改" | 同上 | 560 |
| P3 | 大单 | 运营区"大单"的"改"，或右上的询价 | 同上 | 560 |
| P4 | 风险 | 财务区的"改" | 同上 | 560 |
| P5 | 推流分 | 右上的"推流分" | 推流分的正下方 | 360 |
| P6 | 季度报表 | 播放结束后自动打开；确认之后可以从财务的工作台再打开 | 正中 | 880 |
| P7 | 数字从哪来（含"怎么玩"） | 右上的"?" | 从右边滑出 | 480 |
| P8 | 工作台 | 点功能区的标题 | 从右边滑出 | 560 |
| P9 | 大单货不够 | 播放时模型返回 `pending` | 正中 | 520 |

P9 不能直接关掉：必须选一项。P6 在结论是 `bankrupt` 时也不能关掉：只能点"申请破产"。其余的都遵守下面的规则。

**每个弹窗都必须做到**：

1. 打开：点对应的按钮；或者用键盘走到按钮上按回车。
2. 关闭有三种方式，都要有效：点右上角的叉；点弹窗外面变暗的地方；按 Esc。
3. 打开时后面变暗，后面的东西点不到，焦点留在弹窗里；关闭后焦点回到打开它的那个按钮。
4. 弹窗不超出屏幕。内容太多时，弹窗里面滚动，标题和底部的按钮不动。
5. 手机上从底部升起，占满宽度，最高到屏幕的 85%。
6. 做决定、播放暂停、结算时，P5、P7、P8 都能打开。播放进行中打开弹窗，播放自动暂停，关闭后继续。

**P1 到 P4 的内容**（四个都是同一种结构）：

1. 标题和一句说明。
2. 这一组的参考数字（`docs/06` 第二节），每个数字可以点开看解释。
3. 输入：`Stepper` 或 `Segmented`。打开时是现在的值（第一个季度是参考值，见第五节）。
4. 这一组改了之后，现金计划会变成多少（`docs/06` 第三节）：预计花掉和最坏的季末。
5. 有提示时显示提示（见第五节）。
6. 底部两个按钮："取消"和"就这样定"。点"就这样定"才生效，这一组变成"已定"。

**P6 季度报表的内容**（算法见 `docs/06` 第五节）：

| 部分 | 内容 |
|---|---|
| 标题 | 第几年第几季度的报表 |
| 收入和支出 | 按功能区分三块（进货、运营、财务）。每块里按 `kind` 分行：名字、多少笔、合计。点一行展开看每一笔（编号、日期、金额） |
| 核对 | 一行等式和"已核对"的印章（`docs/07` 第 6.9 节）。`verifyQuarter` 不成立时显示红色的"对不上"印章，"确认报表"不能点 |
| 计划和实际 | 季初的现金计划和实际的对比 |
| 带到下个季度的 | `carryOver` 的四样 |
| 这个季度的结果 | 零售发出多少、缺货多少；大单中了几张、交了几张；推流分和变化；最多 3 句"为什么" |
| 结论 | 付得起：一句话和"确认报表"。付不起：一句话和"申请破产"（只有这一个按钮）。封店或一局结束："看结果" |

**P8 工作台的内容**：顶部三个页签（进货、运营、财务），打开时停在点的那个功能区上。

| 功能区 | 分几块 | 每一块列什么 |
|---|---|---|
| 进货 | 补货单；库存；大单备货 | 补货单：编号、下单日、件数、每件多少钱、到货日、状态。库存：现在多少、留给大单多少、够卖几天。大单备货：每张要多少件、发货日、现在够不够、差多少 |
| 运营 | 零售；路上的订单；广告；大单报价 | 零售：这个季度来了、发出、缺货、签收、退货各多少。路上的订单：每一批的发出日、单数、预计签收日。广告：出价、预算、实际花费、点击、订单、每单广告费。大单报价：每张报没报、报多少、中没中、对手报多少 |
| 财务 | 账单；回款；大单的钱；风险 | 账单：这个季度到现在的每一笔，和以前季度的报表入口。回款：每一批多少钱、预计到账日、状态。大单的钱：定金、尾款、到账日。风险：等级、做过几次合规、有没有被审核过 |

工作台只能看，不能改。每一件事带一个状态标签（`docs/07` 第 6.10 节）。数据全部用 `selectors.ts` 从 `GameState`、事件和账单里取。

## 五、输入规则

超出范围时不自动改成边界值，而是显示出错并说明原因，"就这样定"不能点。**现金够不够不算出错**，只在现金计划里显示。

| 输入 | 最小 | 最大 | 每次加减 | 第一个季度打开时 | 以后打开时 | 出错时的说明 |
|---|---|---|---|---|---|---|
| 第一批进货（件） | 起订量 | 供应商月上限和买得起的最大件数里小的那个 | 10 | 买得起的件数的一半，不低于起订量 | | "最少 {moq} 件""最多 {max} 件" |
| 每月补货量（件） | 0，或者不小于起订量 | 供应商月上限 | 10 | 0 | 上个季度的值 | "要么是 0，要么最少 {moq} 件""供应商一个月最多给 {cap} 件" |
| 售价（林吉特） | 商品的最低价 | 商品的最高价 | RM 1.00 | 参考价 | 上个季度的值 | "这种商品只能卖 {min} 到 {max}" |
| 广告出价（元） | 0 | 对手出价的 3 倍 | ¥0.01 | 0 | 上个季度的值 | "最多 {max}" |
| 每日预算（元） | 0 | ¥9,999 | ¥10 | 0 | 上个季度的值 | "最多 ¥9,999" |
| 大单报价（林吉特） | RM 0.10 | 批发参考价的 2 倍 | RM 0.10 | 不报 | 不报 | "最多 {max}" |
| 合规、升级 | | | | 不做 | 不做 | |

第一个季度打开时的值只是起点，不是建议。每个功能区都要玩家点过一次"就这样定"，才算"已定"。

提示（不拦住操作，用 `goldSoft` 底色的一行）：

| 条件 | 文字 |
|---|---|
| 改完之后最坏的季末是负数 | 如果这个季度一单都卖不出去，季末会差 {gap}。季末付不起，只能申请破产。 |
| 广告出价低于对手出价的一半 | 这个价抢不到流量。 |
| 大单报价低于进价加运费 | 这个价交一件亏一件。 |
| 报了某张大单，按现在的进货计划到发货日货不够 | 到第 {day} 天要有 {qty} 件货，按现在的计划还差 {short} 件。 |
| 每月补货量超过供应商上限的那部分 | 供应商一个月最多给 {cap} 件。 |

"按现在的进货计划到发货日货不够"用 `docs/06` 第二节的 `expMonthly` 估算：`stockQty + 发货日之前到的月初补货次数 × 每月补货量 − Math.ceil(expMonthly × (发货日 − 季度第一天) / 30)`。

## 六、反馈和界面上的动画

| 操作 | 反馈 |
|---|---|
| 在弹窗里点"就这样定" | 弹窗关闭；这个功能区的标签变成"已定"，底色变成 `seaSoft`；底部的现金计划立刻换成新的数 |
| 三个功能区都定好了 | 主要按钮从灰色变成金色 |
| 点主要按钮 | 0.5 秒之内开始播放 |
| 提醒出现 | 功能区上方的小牌子从下往上出现，停 3 秒后收起 |
| 确认报表 | 弹窗关闭，主要按钮亮起 |
| 结局里重算"最关键的决定" | 超过 0.3 秒还没算完，显示"正在重算……" |

界面上的动画只有这几种：弹窗打开和关闭（0.2 秒）；按钮按下；小牌子出现；印章盖下来（0.25 秒）；数字变化时滚动到新值（0.4 秒）；换季节时颜色过渡（0.6 秒）。世界里的动画见 `docs/10` 第六节。

## 七、空的和异常的情况

| 情况 | 怎么显示 |
|---|---|
| 现金是 0 或负数 | 现金用 `hibiscus` 色 |
| 库存是 0 | 库存用 `hibiscus` 色；世界里出现"缺货"牌子 |
| 跨境直发 | 不显示风险等级；财务区的决定是"升级成本土店"，写出要花多少；不升级时写"不升级" |
| 这个季度没有询价单 | 不显示询价；运营区的"大单"写"这个季度没有询价"，不用定 |
| 工作台里某一块没有内容 | 写一句："现在没有在路上的补货。"这样的话 |
| 浏览器不能用本地存储 | 首页不显示最好成绩，其他照常 |
| 浏览器不支持 3D | 见 `docs/10` 第七节 |
| 手机横屏 | 整屏只显示"请把手机竖过来" |
| 代码出错 | 显示一屏："出错了。刷新页面可以重新开始。"下面用小字显示种子编号 |

## 八、无障碍

1. 所有按钮和输入框都有文字名称，读屏软件读得出来。
2. 世界的画布有一句文字说明，并且每个季度更新（例如"第四季度。库存 320 件，路上的货 86 件，路上的货款 2140 元"）。
3. 世界里的信息在别的地方也有数字，不看世界也不会漏掉信息。
4. 焦点顺序：时间线、状态、询价、进货、运营、财务、现金计划、主要按钮。
5. 键盘：1、2、3 打开进货、运营（零售）、财务的弹窗；回车等于点主要按钮；Esc 关闭弹窗。

## 九、三个只给开发用的页面

| 网址参数 | 内容 |
