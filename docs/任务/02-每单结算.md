# 任务 02：每单结算

开始之前先读：`AGENTS.md`、`docs/02-开发约定.md`、`docs/03-每单结算规则.md`。

任务 01 完成并提交之后，才做这个任务。这个任务只写计算代码和测试，不改界面。

## 一、要做的事

### 1. 补全参数表

把 `docs/03` 第八节表格里的参数全部加进 `src/params/malaysia.ts`。名称、值、单位、等级、说明都照表格写。`public` 全部设为 `true`。

### 2. `src/engine/settle.ts`

按 `docs/03` 第九节，实现三个函数：

- `crossShippingSen(weightG, params)`
- `settleOrder(input, params)`
- `unitProfit(input, params)`

要求：

- 算法照 `docs/03` 第四节到第七节。
- 所有数字从参数对象里取，代码里不直接写 18、12、378 这样的数字。
- 按比例的费用只用 `applyBp`。
- 输入不合法时抛出错误，错误信息用英文，说明是哪个字段不对。

## 二、测试

1. `docs/03` 第五节的运费核对表：13 个重量，每个一个测试（`[G03-5#01]` 到 `#13`）。
2. `docs/03` 第 10.1 节：11 条用例，每条检查全部 10 个数字（`[G03-10.1#01]` 到 `#11`）。
3. `docs/03` 第 10.2 节：4 条用例（`[G03-10.2#01]` 到 `#04`）。
4. `docs/03` 第 10.4 节：500 组随机输入，检查 4 条关系。随机数用 `src/engine/rng.ts`，种子固定。
5. 不合法的输入会抛出错误：`priceSen` 是 0、是负数、是小数；跨境直发时 `weightG` 是 0。

核对用例里的数字照抄，不要改。算出来不一样时的处理办法见 `docs/02` 第八节第 4 条。

## 三、完成的标准

- `npm run check:full` 通过，任务 01 的测试也仍然通过。
- 已经提交 git，`开发日志.md` 里有记录。
- 检查员的结论是通过（`docs/13` 第五节）。
